# Phase 3 — 2.9.10 RC stabilization

Baseline: COMPANION-TESTING `e55dad8a0213ddbc1a6873db5558d6b53f6b613d`, version
2.9.9 RC. Original Companion repository is untouched. This is a targeted patch;
no rebuild, UI redesign, dependencies, prompt edits or storage migration.

## Confirmed causes and changes

1. `healRecent` previously inserted a text-length key before metadata commit. A
   transient failure permanently suppressed retries for that key. Complete keys
   now include chat/message/swipe/source fingerprint, are inserted after a successful
   handler/verified report, and retain at most 200 completions. An in-flight map
   serializes recovery per reply and is released on success/failure. Retry uses
   existing processing and message verification, with no added history fetch/scan.
   Existing report replacement/folding, combat/injury snapshots and chapter guards
   remain; no new transaction application path is introduced.
2. The one-second frontend timer requested full state every sixth tick regardless
   of visibility, and backend pushes repainted hidden content. Automatic state
   requests and main-panel DOM updates now defer while its actual content is
   hidden. Intersection/owner-document visibility observers follow drawer, float,
   minimized float and popout independently. Opening flushes the latest local state
   and requests one catch-up, retaining pending name refresh and current chat IDs.
   Older hosts without visibility support fail open. No new timer is introduced.
   Generation relay, background tracking, prompt-time processing, encounter handling
   and normal tracking pushes remain active. This optimizes unnecessary hidden UI
   work without suppressing required tracking work.
3. CPU sampling of 100 source-bound 600-message panel reads identified
   `getSwipeData` as a hot function (261 self samples, compared with 54 for
   `messageSource` and 66 for `agendaRead`; sampling is not precise attribution).
   The live-metadata fast path avoids fallback-array allocation; absent/unsigned
   legacy reports no longer compute an unused fingerprint. Signed live/exported/
   nested candidates still validate current content and active swipe; invalid live
   data still permits valid exported fallback. No metadata-result cache or weaker
   invalidation rule was added. `statesReading`, relationships and Agenda retain
   their existing semantics and read-pass caches.
4. `tools/rebuild.py` default generation could overwrite modern runtime files with
   historical 2.8.2 output. It now refuses in-place generation and modern in-place
   checks, requiring `--output /outside/checkout` for historical output. Preflight
   resolves every target before writing and rejects symlinks into the checkout.
   Historical generation/overlays remain intact. Explicit external generation and
   subsequent `--check --output` both pass.

## Regression and correctness evidence

- New recovery test fails against 2.9.9 at the retry assertion before the patch.
  Current tests cover transient pre-commit failure, metadata-only partial write,
  commit-then-error, deletion, edited content, swipe changes, concurrent snapshots,
  equal-length edits, stale completed snapshots and bounded retention. Folded XP,
  money, inventory, relationships and relative Minds effects equal one successful
  processing. Save/help/continuation never commit story transactions. No model call.
- Metadata-read cost test fails against the baseline's unnecessary fingerprinting;
  current signed/unsigned/fallback/edit/continuation cases pass.
- Four browser visibility tests fail against the original frontend and pass current:
  hidden idle/render deferral and catch-up; edits/deletes/swipes/persona/chat changes
  plus generation relay; minimized float independent of drawer; popout/return.
  Incoming hidden state (including NPC changes) is kept and rendered on reopening.
- Historical overwrite refusal test fails against the old tool in a disposable fake
  root. Current refusal paths leave the fake modern file unchanged and reject
  checkout/symlink destinations. Real historical output is generated only outside
  the checkout and verifies reproducibly there.
- Release gate: **26 suites plus both bundle syntax checks pass**, including all
  existing 23 suites, supported world/card fixtures, source-bound persistence,
  Save/Continue and Internal States. **13 real Chromium checks pass** (nine
  existing plus four visibility). Browser bridge/provider remain mocked.
- The active runner intentionally excludes archived source-text-only compatibility
  groups. An exploratory unfiltered old source-integrity harness has the same two
  HUD/source assertion failures on 2.9.9 and candidate; its six active tracking
  groups pass. No assertions were weakened and no unrelated HUD rewrite was made.

Node 22.22.2, same cloud host, identical fixtures. Five alternating baseline/candidate
panel rounds, source-bound 300/1,000 assistant readings plus user turns; each cold
read precedes three warmups and ten samples. Pipeline and GC-assisted VM memory
measurements use three alternating rounds. Raw measurements and methodology:

Both versions' normal Separate update makes one model call, six history API fetches,
one metadata write, two storage reads, four storage writes (primary/recovery
snapshots), and three state payloads. The instrumented panel retains 9,101 history
index accesses and the same traversal families. Counts are fixture-specific, not
proof for every optional subsystem. Failure retries necessarily retry the failed
commit; no extra normal-path call or scan was introduced.

A hidden, initialized panel makes **zero** heartbeat state requests in six ticks,
versus **one** in baseline, and no main-panel replacement on incoming state. Visible
heartbeat remains one request per six ticks, with one visibility catch-up. These are
bridge/local CPU tests, not provider/network benchmarks. Frontend memory and live
host storage latency are not measured; VM heap numbers are not a long-session leak
claim. Recovery retention is bounded and tested. The retained fast path demonstrates
600-message benefit without a material larger-history regression; no long-history
speedup or blanket responsiveness claim is made.

## Preserved behavior and deliberate limits

Scheduled Agenda remains separate from NPC routines. Quests, stages, rewards,
completed history, NPC/family persistence, owner/private knowledge and UI/settings
are unchanged. No spell/technique state-machine redesign or speculative cache was
introduced. Keep signed per-swipe checks, continuation display/transaction boundaries,
write queues, recovery copies and shared read passes.

This candidate still needs live Lumiverse installation/update/reload and extended
full-card sessions. Fixture tests do not certify every supported card playthrough.
The removed old request-purpose prompt layer was not reinstated. No claim is made
that all of the earlier 2.9.3-to-2.9.9 cost has been removed.

## Release verification and rollback

Version/identity must agree in spindle.json, backend diagnostics, drawer and popout.
CI validates the exact checkout with read-only permissions, runs all 26 suites,
packages into a temporary directory and runs both Chromium suites. The retired
source-copy/publish workflow is not restored. Publication is performed separately
only after hosted checks pass, with uploaded/downloaded ZIP hashes compared.

Rollback baseline is preserved by commit `e55dad8` and tag
`phase3-baseline-2.9.9-rc`. The previously tested local 2.9.9 ZIP has SHA-256
`43d9e9fc15bcc1a57f4fa65ec8f52b0ec63756e850e8cc37123780d2d5342ebc`;
its runtime and manifest match the saved baseline byte-for-byte. No migration or
schema change is introduced, and rollback must preserve chat/settings data. Use a
reviewed rollback commit/older package through the host's supported install/update
procedure; do not delete saved metadata or use the historical 2.8.2 generator.
