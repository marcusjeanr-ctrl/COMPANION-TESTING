## Removal method and retained dependencies

Eight separate reverse commits remove the requested excluded additions, with
manual conflict resolution preserving the included features. This is source
removal, not hidden UI or default-off code. Their controls, translation keys,
handlers, exclusive helpers, tests and feature documentation are removed.
Version identity remains 3.2.0 RC in manifest, diagnostics, drawer and popout titles.

Only necessary shared dependencies remain:

- A bounded voice-only dialogue reader is requested only by an open NPC editor.
  It reads at most 40 recent positions / 10 visible story replies, with source and
  visible-character limits; hidden content, HUD and reasoning are excluded.
- The existing context-budget append helper supports accepted voice notes only.
  The reminder defaults OFF, uses present NPCs only, adds at most 240 characters,
  and never displaces lore or creates a context section. Default prompts stay the same.
- Optional full-date provenance in the existing Chronicle projection prevents
  daily bond groups from crossing months with identical day numbers. It neither
  changes the visible source timestamp nor stores or rewrites reports.
- The pre-existing Factions parser's case-insensitive legacy `reputation` alias is
  retained in lowercase. This preserves existing HUD compatibility while allowing
  the exact requested UI-name scan to return no matches. No new view remains.

No saved reports/settings are rewritten to purge old optional keys. Unknown
legacy data remains ignored and preserved by existing storage handling. Accepted
voice notes use only optional `playNotes.voice` (60 entries maximum); rejected
new entries do not evict saved notes or erase the unsaved editor.

## Verification

Selected-candidate checks and the revised gate are recorded below after completion.
The standard full runner includes 61 JavaScript suites, both syntax checks and
12 Python gate tests. Chromium uses a mocked bridge, not an installed host.
No paid provider request is made. The voice opt-in is tested off/on/off through the
actual interceptor; no new automatic model calls, polling or timers are added.

The revised [CPU/wall rule](GATE_REVISION.md) uses 20 alternating observations per
source/case (600 and 2,000 messages), cold/warm medians, IQRs and same-source spreads.
A failure requires both 2,000-message warm metrics above +5% and both differences
above the respective baseline run-median IQR. Noisy/one-metric excess is explicitly
inconclusive. Historical 3.0.10 is informational. Full raw records are retained;
no outcome is selected by discarding or silently rerunning measurements.

## Remaining limits

Live Lumiverse installation/update, Android WebView, provider behavior and real
campaign UI latency remain unverified. Dossier history/evidence reflect retained
observations, not invented lifetime totals. Conservative display matches can leave
uncertain paraphrases separate. Reliable acceptance/routing findings remain
investigation-only; no progression or gameplay rule is changed. Model attribution
remains deferred. This is a review candidate with no stable-release claim.
