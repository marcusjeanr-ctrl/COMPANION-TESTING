# 3.1.0 RC staging feature verification

Branch: `staging/features-3.1`. Baseline: `540df20f602bd475b9149c1ab28aa705e391f72d` (3.0.10 RC).
No live Lumiverse instance has been used. Chromium uses a mocked host.
Runtime source is the checked-in `dist/backend.js` and `dist/frontend.js`.
Only their marked translations/guides are generated by `tools/embed_i18n.py`.

## 1. Consistency checker

Optional advisory table: missing readable HUD, raw backward clock/date, and
opposite explicit `Field: active|inactive|enabled|disabled [at rest]` directives.
Start input is retained only in the existing shared continuity-index traversal;
matching cached start-handler rules are read without loading additional lore.
Conditional rest checks require an explicit resting HUD field. Unsupported prose
rules are deliberately unverified; no rules engine, corrections or writes.
Warnings can include intentional rewinds: they are advisory, never corrections.
Source changes: both runtime files and four translation dictionaries (English
is the source key); new `tools/test_features_3_1.cjs` registered in the suite.
Checks cover missing HUD, raw time regression, start/card setting conflict,
non-rest exclusions and disabling. All 52 suites and release identity passed.

Initial benchmark baseline → feature 1: warm panel 63.04 → 61.33 ms;
cold panel 284.24 → 347.57 ms (+22.3%); parse 0.5568 → 0.5714 ms;
response 0.7823 → 0.8343 ms (+6.6%); prompt construction 0.3767 → 0.3717 ms.
These are single cloud measurements, not demonstrated causal slowdowns.
Prompt lengths unchanged (15,291 / 19,213 characters). Final alternating paired
measurements will check the >5% observations before acceptance.

## 2. Family location labels

Frontend-only: off-scene `seen`/`told` locations say last seen/last known with
existing in-game age. Guesses retain their uncertainty label. Old activity is
secondary inside a closed Last reported activity disclosure; current reports
remain visible. No stored `where`, timestamps or presence rules change.
Regression checks a 30-minute scene departure, retained location/activity and
byte-identical input. All 52 suites/release checks passed. English source keys
and all four dictionaries updated and embedded. See per-feature benchmark table.

## 3. Scene-cast reminder

The existing one-line previous-character JSON is now labelled `Present now
(check):`. This deliberately reuses the names AND existing details rather than
adding a second list or losing previous-panel context. It remains a reminder to
verify against the current response, not proof that absent characters are still
present. Both Together and Separate prompt paths tested. Exact character budget
is unchanged, with no state, schema, refresh or model-call changes. All 52 suites
and release checks passed. This cannot independently recover an unreported cast.

## 4. Character-sheet export

Frontend-only local Markdown download: HUD (including tiers), confirmed Known/
Mastered catalogue rows, labelled abilities, gear, family, open/completed/other
ended quests and key relationship labels. The full catalogue is never exported
as player knowledge. No private Minds monologues, calls, chat writes or stored
changes. Markdown data is escaped; Blob URLs are revoked without timers.
Synthetic regressions verify learned-vs-reference separation, empty state,
quest statuses, relationships and immutable input. All 52 suites and release
checks passed; native host download handling still needs live verification.

## 5. Named snapshots

Additive optional `trackerSnapshots`, sequence and active-view keys in the
existing per-chat store. Maximum ten named views, 80-character names and
300,000 characters per view; oversized requests are refused. Validation is
cached per array with a WeakMap, so ordinary updates do not repeatedly serialize
saved snapshots. Old chats need no migration. Existing serialized state/recovery
writes are reused only on explicit user action. No message metadata is changed.

**Review decision:** Restore means restore an isolated read-only view, not roll
back the live tracker. The active view survives reload and has Return to live
tracking. It is never used for prompts, transactions, live HUD or manual edits;
knowledge/items/XP cannot be granted by restoring. This is deliberately safer
than replacing live state beneath an authoritative HUD. Private Minds data in a
snapshot remains local to extension storage. Native host reload is unverified.

Tests cover bounded eviction, missing IDs, old saves, view persistence, oversized
input, return to live, immutable seed/XP/spellbook and zero metadata writes.
All 52 suites/release checks passed, including a rerun after caching validation
and clearing snapshot UI on chat switch. Backend/frontend plus dictionaries changed.
