## 1. Consistency checker

Optional advisory table: missing readable HUD, raw backward clock/date, and
opposite explicit `Field: active|inactive|enabled|disabled [at rest]` directives.
Start input is retained only in the existing shared continuity-index traversal;
matching cached start-handler rules are read without loading additional lore.
Conditional rest checks require an explicit resting HUD field. Unsupported prose
rules are deliberately unverified; no rules engine, corrections or writes.
Warnings can include intentional rewinds: they are advisory, never corrections.
Source changes: both runtime files and four translation dictionaries (English
is the source key); new `tools/test_features_3_1.cjs` registered in the suite.
Checks cover missing HUD, raw time regression, start/card setting conflict,
non-rest exclusions and disabling. All 52 suites and release identity passed.

The initial exploratory baseline command overlapped early development, so its
numbers are excluded from acceptance. Final comparisons below read the exact

## 2. Family location labels

Frontend-only: off-scene `seen`/`told` locations say last seen/last known with
existing in-game age. Guesses retain their uncertainty label. Old activity is
secondary inside a closed Last reported activity disclosure; current reports
remain visible. No stored `where`, timestamps or presence rules change.
Regression checks a 30-minute scene departure, retained location/activity and
byte-identical input. All 52 suites/release checks passed. English source keys
and all four dictionaries updated and embedded. See per-feature benchmark table.

## 3. Scene-cast reminder

The existing previous-character context is split into one concise `Cast to
check: [names]` line and same-order detail rows. Every existing field is retained
without repeating each name. Tests enforce a length no greater than the previous
block, including a one-person name-only record. The unchanged physical-presence
instruction still requires checking the current response; this reminder is not
proof of presence and cannot independently recover an unreported cast. Both
Together and Separate paths are covered. All 52 suites/release checks passed at
the feature checkpoint; final acceptance also checks the compact representation.

## 4. Character-sheet export

Frontend-only local Markdown download: HUD (including tiers), confirmed Known/
Mastered catalogue rows, labelled abilities, gear, family, open/completed/other
ended quests and key relationship labels. The full catalogue is never exported
as player knowledge. No private Minds monologues, calls, chat writes or stored
changes. Markdown data is escaped; Blob URLs are revoked without timers.
Synthetic regressions verify learned-vs-reference separation, empty state,
quest statuses, relationships and immutable input. All 52 suites and release
checks passed; native host download handling still needs live verification.

## 5. Named snapshots

Additive optional `trackerSnapshots`, sequence and active-view keys in the
existing per-chat store. Maximum ten named views, 80-character names and
300,000 characters per view; oversized requests are refused. Validation is
cached per array with a WeakMap, so ordinary updates do not repeatedly serialize
saved snapshots. Old chats need no migration. Existing serialized state/recovery
writes are reused only on explicit user action. No message metadata is changed.

**Review decision:** Restore means restore an isolated read-only view, not roll
back the live tracker. The active view survives reload and has Return to live
tracking. It is never used for prompts, transactions, live HUD or manual edits;
knowledge/items/XP cannot be granted by restoring. This is deliberately safer
than replacing live state beneath an authoritative HUD. Private Minds data in a
snapshot remains local to extension storage. Native host reload is unverified.

Tests cover bounded eviction, missing IDs, old saves, view persistence, oversized
input, return to live, immutable seed/XP/spellbook and zero metadata writes.
All 52 suites/release checks passed, including a rerun after caching validation
and clearing snapshot UI on chat switch. Backend/frontend plus dictionaries changed.

## 6. Relationship web

Frontend-only Minds disclosure, available in HMS and classic tracking panels.
No graph data/layout is computed while closed. Existing directed pair records
supply links; colours explicitly describe the source character's recorded mood,
not inferred reciprocal feelings or a computed relationship score. Neutral grey
means no supported colour. Maximum 19 NPCs plus the player, 80 links; omitted
people are counted. SVG uses a fixed viewBox with responsive width, text-only
labels, full-name titles and an accessible name list. No physics, dependencies,
listeners outside the disclosure, polling or timers. Tests cover caps, membership,
colour mapping and unchanged inputs. All 52 suites and release checks passed.

## 7. Sandbox canon divergence

Frontend-only view reuses the existing Mushoku saga arcs/event ledger plus the

The existing full arc reference view is preserved. Sandbox only; other worlds

Tests cover all four statuses, unknown predictions, future dates, non-Sandbox,

## 8. Compact mobile layout

Optional, default-off setting. At <=480px use one-column cards and a sticky
three-line location/cast/open-quest summary. Twelve reported cast names and two
quest names plus the remaining count bound the header; full panels stay below.
Desktop layout remains unchanged. CSS reflow only: no resize observer/timer.
Browser tests exercise drawer and floating at 320/360px, viewport containment,

warning badge, old Family activity disclosure, actual Markdown download with zero
backend requests, snapshot restore/isolation, lazy graph caps and canon evidence.
The graph test explicitly closes the previous disclosure and waits for native
`toggle` delivery before checking lazy SVG creation. All 52 JS suites and release
checks passed; final complete Chromium rerun follows acceptance refinements.

## Final acceptance refinements

- Start handlers are matched generically, including leading whitespace. Normalize
  their key once per check: a 1,273-entry cached-lore benchmark exposed repeated
  full-command splitting, which is eliminated without changing results.
- Cast names are separated from same-order details without increasing the prior
  prompt budget or discarding fields. The text says **Cast to check**, rather
  than asserting historical cast members are definitely still present.
- Export also includes confirmed unlisted spellbook knowledge and Agenda rows.
- Snapshots omit unlearned catalogue references, retaining known/mastered/studying
  rows. A synthetic 1,000-reference catalogue fits after compaction without
  changing live knowledge. Oversized tracker views are refused at the existing
  300,000-character bound; unusually large campaigns may not fit.
- Current off-scene Family activity stays visually secondary. Graph legends wrap
  unbroken names: a new 320px browser reproduction failed before this correction
  and passes after it. The sticky header follows light/dark theme card colours.
- UI title explicitly says 3.1.0 RC. Manifest/backend version is 3.1.0; the release
  identity check accepts the explicit RC presentation suffix while checking the
  exact semantic version. Identifier, permissions and minimum host version stay.

## Review decisions and remaining verification

1. Start/card contradiction matching recognizes explicit field directives only,
   not arbitrary rule prose, condition systems or combat consequences. Intentional
   rewinds/undated midnight can produce an advisory clock warning. The HUD is
   never corrected; turn warnings off if not wanted.
2. Snapshot restore is a read-only historical view, not a live rollback. Ten
   snapshots / 300,000 characters each are the reviewable bounds. This cannot
   restore deleted chat messages or reverse transactions.
3. Graph link colour is the source character's recorded mood, explicitly labelled
   as such; links come from directed pair data. It does not infer reciprocal
   feelings or assign pair-specific emotions.
4. Canon view lists reported outcomes and the explicit next event; the full arc
   reference remains separate. Unmentioned events stay unverified, not passed.
5. [Quest completion investigation](QUEST_COMPLETION_INVESTIGATION.md): completion
   gates are reproduced, but neither Quest logic nor assignment status is patched.
6. **None of this was tested in a live Lumiverse instance.** Android WebView,
   native download support, real storage/reload, actual narrator/tracker output
   and long-campaign responsiveness still require live acceptance. Chromium is a
   mocked host, and card regression fixtures do not certify every card mechanic.
7. No main merge, extension release, release tag or original-repository write is
   part of this staging task. Draft PR only, for review.
