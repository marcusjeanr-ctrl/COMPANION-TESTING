# Gear containers (experiment)

Branch `experiment/3.6.0-gear-containers` from `staging/3.6.0-ui` at `bf80da9`. Not merged anywhere.

## What existed
Gear already grouped contents ("👜 Inside Travel luggage (4)") as a collapsible group, remembered per bag.
The gap: the group was drawn at a fixed place in the list, separate from the bag's own row, so a dropped bag
appeared under Dropped while its contents appeared above, under no visible bag.

## What changed (`renderGear` in `dist/frontend.js`)
- Contents are drawn inside the bag's own row (`li.rpgc-gear-box`, toggle `.rpgc-box-toggle`, list `.rpgc-gear-inside`).
- Same matching rule as before: `item.state === 'in container'` and `item.inside` equals the container name
  (case-insensitive). Same open/closed key: `gear-box-<name>`.
- Not nested (older behaviour kept): a container with no row of its own; containers in a loop; depth > 4.
- Safety net: items not drawn anywhere else appear under "Other".

## Verification
- `node tools/run_tests.cjs`: pass (the smoke test now checks the nested row, not the old group: expected change).
- `tools/test_ui.cjs` gear block (synthetic inventory with a pouch in a pack, a loop of two chests, a container with
  no row, an unknown container): every item drawn exactly once; correct nesting; loop not nested; closing a bag
  hides its contents and sends no message; bags independent; closed state survives a refresh; Move still sends the
  move. The same block fails on the `bf80da9` frontend (nothing nested there).
- Real data (export 5, Travel luggage dropped with four items inside): checked at 340, 420 and 1000 px.
- `tools/replay_check.cjs` on export 5: 0 problems over 41 replies. `dist/backend.js`: 0 changed lines.

## Not verified
