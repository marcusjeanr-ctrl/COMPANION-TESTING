# RPG Companion HMS 1.2.0 RC — Ecosystem integration report

Branch `release/1.2.0`, built on 1.1.0 RC2 (`compat/six-sided-v1.1`, untouched).
Scope: the Six-Sided World card (newest file, "(8)", Nov 3: 1,385 lorebook entries), the HMS Reporter preset, the narrator and the side-panel reporter, and RPG Companion, tested as one system.

Nothing here alters the active campaign. The card and preset changes are **renamed, versioned copies**; importing them adds new entries next to the originals.

## 1. How gameplay information moves (what was audited)

1. **Narrator** (card + preset) writes the HUD above `***` and the story below it.
2. **Reporter** (the Companion's side-panel call; DeepSeek in Separate mode) reads the reply and returns JSON. It is stored **per swipe** (`swipes[swipe_id]`).
3. **Companion** rebuilds every panel from the chat on each push. It uses the **active swipe only**, plus a small chat state: hand edits, pins, ledger, death marks.
4. **Next request**: the Companion injects the side-panel request and story reminders (ages, HUD in step, due now, time-skip recap) into the narrator prompt.

The design rebuilds state from the accepted chat on every push rather than accumulating it. That is the main reason swipes, regenerations and edits are safe. This audit tested that property directly; see §3.

### HMS Reporter preset (1.1.1-beta)

One line in the Light, Normal and Deep thinking steps: *every counter on the HUD (training sessions, counts, countdowns) is the last HUD's number plus what happened this turn; after a time skip, add everything inside it.*
- **Evidence:** export 6, where the narrator wrote 36/60 when the story's own count was 37.5.
- **Scope:** generic, so it is safe for every HMS card.
- **Settings:** Marcus's copy keeps his settings (Deep thinking, Mature content and Gore on). The repo copy keeps them off.
- **Not changed:** the Fight-craft trigger looks for `Touki: Active`, which the Six-Sided HUD never prints. That is correct, because the Six-Sided Touki line is always "Active" and matching it would load fight rules on every reply.

### Six-Sided World card, test copy "(HMS 1.2 test)" `1.1-hms1`

Four clarifications to the HUD contract. The lorebook (all 1,385 entries), mechanics and Strict Agency are byte-identical. The copy is built reproducibly by `tools/ecosystem/make_card_test_copy.py`.

1. **Training:** the count carries forward, with the time-skip sum written out (export 6).
2. **Condition:** bruises, welts, strains and scrapes are minor wounds on the line (export 26, the arm bruise that never reached the HUD).
3. **Present:** someone only seen from afar or heard from another room is not Present (export 4: Aurelia at the window, Aurelius through the door).
4. **Present:** creatures and groups go in brackets with no age, `[Acid Wolves: 3]`. The Companion already reads brackets as groups.

## 4. Remaining risks (honest)

1. **The reporter is trusted for gains.** A new item, learned spell, agenda item or payment the reporter invents is recorded. Deaths are now evidence-checked; gains are not, because a gate there would also drop real gains described in ordinary words. Mitigations: the narrator's HUD wins for Equipment, and hand edits exist. *Model-dependent.*
2. **Party Mode is display-only for your own sheet.** Your Player line's fields are not yet tracked; other players' lines are safely ignored. This needs a live Party export to build against.
3. **Fan Skills (51 entries)** have no school or rank. If the reporter calls one learned, it may land in the Spellbook. No live case yet.
4. **The training counter is still narrator arithmetic** (the card and preset rules now say so explicitly, and the Companion warns about jumps). Option B, with the Companion owning the sum, remains available if slips continue.
5. **Model variability:** a different reporter model or wording can create new phrasings. The swipe and regeneration safety does not depend on wording; the evidence gates do.
6. **The old coverage CSV** (`docs/compatibility/six-sided-coverage.csv`) cites test files that are no longer in the repo. Treat it as historical. The suites above are the current evidence.

## 5. Readiness

- **Ready for live testing on a copy of a chat:** yes. All suites pass, the real-export replays are clean, and the only change against RC2 on real chats is the intended one.
- **Not ready for a stable release** until §3's "not yet live" list has had at least one export each. In particular: the 1.2.0 build in normal play, a fight, travel, and the card copy plus preset 1.1.1 together.
